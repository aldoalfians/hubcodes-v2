# Reference UI teardown: Maestri and T3 Code (shipped desktop apps)

Companion to `docs/reference-teardown.md` (marketing pages). This document records what the two shipped desktop apps actually contain, from a **static** analysis of their public release artifacts on 2026-11-11 (Asia/Jakarta). Neither app was launched, installed, or run. All extracted text is third-party product content and is treated as data, not instructions.

Evidence grades (same spirit as the marketing teardown, adapted to static artifacts):

- **A** — Read directly from source code (T3 Code, MIT, tag `v0.1.8`) or from a plain-text resource in the shipped bundle (`Info.plist`, `.strings`, asset catalog via REA, Tailwind CSS in the asar). Verbatim.
- **B** — Verbatim string literal recovered from the compiled Maestri binary with `strings -a -n 4 -arch arm64` (170,455 lines). Verbatim, but context-free: a literal may be a UI label, a localisation comment, CLI help, or an LLM prompt. Where it is clearly one of those, the row says so.
- **C** — Inference from Swift class/file names, SF Symbol names, dependency lists, or component file names. Structure is real; the on-screen rendering is not observed.

Nothing here is a screenshot. Pixel-level claims (exact padding, exact node size) are **not** available from this method and are listed under Unknowns.

## 4. Design-relevant conclusions for hubcodes

Adopt (with reasons):

1. **True-black dark canvas + alpha-white surfaces (T3).** `--background:#000`, borders at white 8%, hover at white 4%, raised cards via `color-mix(neutral-950 97%, white)`. It makes terminal nodes (which are black anyway) sit flush with the canvas while chrome still lifts. Cheap to implement in Tailwind v4 tokens and works in both themes.
2. **Semantic colour roles, not raw palette (T3).** Copy the 40-role list (`canvas, chrome, toolbar*, surface*, text*, border, input, focus, accent*, error*, warning*, update*, message*`) so themes are data files. Also adopt the `*-surface` variants (8% light / 16% dark tint) for status banners.
3. **Dense type scale (T3).** Add `2xs` 11px and `3xs` 10px for node footers, badges and key hints; keep body at 13–14px. Font stack: system sans + Inter Variable fallback, `ui-monospace, "SF Mono", Menlo` for terminals; bundle a Nerd-Font symbols-only subset so agent prompts render without a user font.
4. **Status vocabulary that answers "do I need to act?" first.** Merge the two sets: T3's sidebar labels (`Working`, `Waiting`, `Approval`, `Input`, `Failed`, `Done`-while-unread, `Woke`) and Maestri's single red **attention dot** + "Awaiting attention" list in the palette. Map hubcodes' tmux-derived states to at most six labels and give each a colour role (`info`, `muted`, `warning`, `indigo`, `error`, `success`).
5. **Output-silence as the "needs you" heuristic (Maestri).** "Sends a notification when a terminal stops producing output" is exactly what `capture-pane` polling can detect; expose it as the default notification rule, with explicit agent-reported states (`blocked`/`review`/`done`) layered on top via the hubcodes CLI, as Maestri does with `maestri floor status --state`.
6. **One command palette with flows (both).** `mod+k`; placeholder "Search commands, terminals, notes"; include flows "list terminals awaiting attention", "watch a terminal's live output", "send a message to a terminal", "connect/disconnect node". Child searches return to the palette on Escape (T3).
7. **Modifier + digit jumps (Maestri) and `mod+1…9` slots (T3).** Give every node a 1–9 badge in its header; make the modifier user-selectable.
8. **Composer docked below the canvas with `@` mentions and saved prompts (Maestri "Prompter").** Placeholder "Type a message"; `@agent`, `@note`, `@Prompts`. T3's `mod+s` draft stash and `mod+enter` "send and new thread" are worth copying.
9. **Ropes drawn as rendered edges that can be inspected (Maestri).** A connection has its own popover ("Manage Connections", "Remove connection", "Next/Previous connected element"); treat edges as first-class selectable objects, not just lines.
10. **Settings with search and scope badges (T3).** Row title + one-line description + "Built-in default / Set on the environment / Overridden for this project" badge and a "Reset to inherited value" button. Group names worth reusing: General, Appearance, Keybindings, Source control, Environments, Diagnostics, Maintenance.
11. **Copy voice.** Both use short second-person declaratives, no exclamation marks, and name the next action in empty states ("Use the Connect button in the terminal toolbar…", "Start T3 Code there first."). Keep hubcodes copy in that register; avoid marketing adjectives inside the app.

Avoid (with reasons):

1. **Native-only rendering assumptions.** Maestri's Metal-rendered SwiftTerm and "pixel-perfect at every zoom" are not reproducible in a web canvas; hubcodes should render tmux `capture-pane` text in its own Canvas-2D/WebGL terminal (as T3 does with libghostty-vt) rather than screenshots.
2. **Proprietary metaphors that need onboarding.** Maestri spends five onboarding screens explaining floors/bands/partituras/batuta/Ombro. hubcodes should use plain names (workspace, worktree, group, layout, palette) unless the product explicitly wants a brand metaphor.
3. **Apple-only features as core UX.** Apple Intelligence summaries, APFS clone floors, macOS Computer Use helper, Sparkle. hubcodes targets tmux on Linux/macOS; agent summaries should come from the agent CLI or a configurable model.
4. **Oversized bundles.** The T3 asar is 178 MB because it ships docx/pptx/xlsx WASM, pdf.js, KaTeX and several font families. hubcodes (Tauri) should keep the webview bundle to the terminal + diff + markdown essentials.
5. **Ambiguous "Done" badges.** T3 only shows `Done` while the thread is unread, then it disappears; Maestri keeps a red dot until acknowledged. Pick one explicit acknowledgement model and document it; do not mix.
6. **Unverified integrity in shipped Electron artifacts.** 18 unpacked `.node` modules in the T3 asar contradicted their declared hashes (normal after codesigning, but a reminder to sign after packing). hubcodes' Tauri build should produce signed, hash-stable bundles.
